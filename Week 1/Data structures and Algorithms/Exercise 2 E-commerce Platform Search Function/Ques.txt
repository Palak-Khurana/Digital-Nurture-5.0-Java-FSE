o	Explain Big O notation and how it helps in analyzing algorithms

Big O Notation is used to measure the performance of an algorithm as the input size increases.

It tells us how the running time or memory usage grows with the number of elements.

Common Complexities
Big O	        Name	   Example
O(1)	      Constant	  Accessing an array element
O(log n)	Logarithmic	  Binary Search
O(n)	       Linear	  Linear Search
O(n log n)	Linearithmic  Merge Sort
O(n²)	     Quadratic	  Bubble Sort

o	Describe the best, average, and worst-case scenarios for search operations.

Search Operation Scenarios
Best Case

The element is found immediately.

Example:

[101,102,103,104,105]

Search 101

Found at first position.

Linear Search = O(1)
Binary Search = O(1)
Average Case

Element is somewhere in the middle.

Linear Search = O(n)
Binary Search = O(log n)
Worst Case

Element is last or not present.

Example:

[101,102,103,104,105]

Search 999
Linear Search = O(n)
Binary Search = O(log n)

Analysis
Time Complexity Comparison
Search Algorithm	Best Case	Average Case	Worst Case
Linear Search	      O(1)	       O(n)	           O(n)
Binary Search	      O(1)	     O(log n)	     O(log n)

Example
Suppose an e-commerce platform has:

1,000,000 products
Linear Search

May need to check:

1,000,000 products

Time Complexity:
O(n)

Binary Search

Checks approximately:

log₂(1,000,000) ≈ 20 comparisons

Time Complexity:

O(log n)

Much faster.

Which Algorithm is More Suitable?
Binary Search is More Suitable

Reasons:

Faster searching for large datasets.
Time complexity is O(log n).
E-commerce platforms may contain millions of products.
Improves user experience by providing faster search results.
Limitation

Binary Search requires the data to be sorted by productId.
